# 聚合/去重类视图功能:先用数据量化重合度再决定做不做

> **结论速览**:做"去重/聚合/关联"类视图前,先对全量数据跑两级量化(精确归一化匹配 → 模糊相似度),重合度不支持就挂起——本次实测把"三站大量互转"的旧观察修正为"真重复仅 2-3 组",避免建出一个空视图。
> **适用条件**:任何"把多来源内容归并展示"的功能决策;数据已在库中可全量查询。

## ✅ 两级量化口径:精确匹配测下界,模糊匹配测上限,数字说话(2026-09-29)

- **为何值得记**:二期规划里有"跨站去重视图",依据是用户观察"三站互相转载、大量重复内容"(已写入交接文档);若直接动手,做完会发现视图常年空白。两级量化各 20 行脚本、分钟级成本,避免了整个功能的无效投入。
- **最终方案**:

- **为什么这样做**:精确匹配回答"有没有可直接归并的"(本例 0 组);模糊匹配回答"语义级重复有多少"(本例 5 对、真重复 2-3 组)。两级之间的大空白说明重复内容即使存在也已被各站深度改写,归并展示的准确性无法保证。
- **适用条件**:语料规模在几百到几千篇(全量两两比对可行);归一化规则按站点标题风格定制(如 hl365 的日期前缀)。语料上量后(数万篇)需换 MinHash/倒排索引,结论需重测。
- **验证证据**:356 篇全量实测(2026-09-29):归一化标题跨站精确匹配 0 组;2785 个图片 URL 跨站共用 0 个;模糊匹配(≥0.5)仅 5 对,人工复核真重复 2-3 组。数字存档于 `docs/handoffs/melon-hub.md` 2026-09-29 增量块。
- **交叉验证**:单 agent 单轮 + 红队自审(发现"精确匹配 0 组 → 建议砍掉"与既有"大量互转"观察矛盾后,补做模糊匹配修正为"挂起"),证据入口同上。
- **关键步骤**:先查既有文档中的"用户观察/旧结论"→ 实测校验 → 矛盾时升级口径(精确→模糊)再定论,不跳级。
- **易错点**:
  - 模糊匹配有假阳性:同剧集不同集数(第 13 集 vs 第 1 集)相似度 0.52,须人工复核,不能拿相似度阈值直接当去重依据。
  - **写进交接文档的用户观察性结论("大量互转")同样要用数据校验**,不能因为是既有记录就直接采信为功能依据;但推翻时也给修正结论(挂起而非砍掉),尊重观察可能随语料增长成立。
